1.1 Virtual Machines 20 min

A virtual machine (VM) is a software-based computer running inside a physical server. The hypervisor manages multiple VMs on one physical host — the same concept as AWS EC2, just running locally on Proxmox.

📸
Instructor Demo · Proxmox Web UI
Browser showing Proxmox web interface — left panel with node tree, centre showing VM list with CPU/memory allocations, one VM console open. Point out: node (physical server), VMs, resource bars.
⚡ Isolation
A crash in VM 1 doesn't affect VM 2. Each VM has its own OS, memory space, and disk.
📸 Snapshots
Save a VM's state at any point. Roll back if something breaks — used for backups and testing.
🐌 Startup
VMs boot a full operating system — takes 1–5 minutes. Containers start in under 1 second.
1.2 Containers and Docker 40 min

A container packages an application with everything it needs — code, libraries, config — but shares the host OS kernel. No duplicate operating system per container.

🏨 VM — The Hotel Suite
Has its own full kitchen, bathroom, plumbing
Completely self-contained — heavy & slow to set up
Gigabytes in size, minutes to start
Best when: you need different OS types, full isolation
🏢 Container — The Hotel Room
Shares the hotel's plumbing & electricity (OS kernel)
Smaller, faster to check in/out — still isolated
Megabytes in size, seconds to start
Best when: same OS, multiple services, fast deploys

Docker is the most widely used container platform. It has four key components:

📋
Dockerfile
The recipe. Text instructions that tell Docker what to put in the image.
FROM · COPY · EXPOSE
📦
Image
The built result. A read-only snapshot — like a sealed package that can be copied anywhere.
docker build
🐳
Container
A running instance of an image. Many containers can run from one image simultaneously.
docker run
🌐
Docker Hub
Public registry of pre-built images — nginx, mysql, redis, node. Like an app store for containers.
hub.docker.com

docker run -d -p 3000:80 my-app:v1.0  # Run container in background, map ports
docker ps                              # List running containers

docker images                          # List all images on this machine

docker exec -it <name> sh              # Open a shell inside a running container
🎯 Common confusion: Image ≠ Container. Image = the recipe (static). Container = the running app (dynamic). You can run 5 containers from 1 image — like printing 5 copies of a document from the same template.

3 Cloud Storage Solutions 60 min

Cloud storage comes in three types. Each solves a different problem. Choosing wrong wastes money and causes performance issues.

📁
File Storage
Folder-and-file hierarchy. Multiple machines can read/write the same files simultaneously.
NFS · Samba · AWS EFS
💽
Block Storage
Raw disk blocks — no file structure. The OS treats it like a hard drive plugged in directly. One machine at a time.
iSCSI · AWS EBS · Azure Disks
🗄️
Object Storage
Flat objects (files) accessed via HTTP REST API — PUT, GET, DELETE. No mounting needed. Scales to billions of files cheaply.
AWS S3 · Azure Blob · MinIO
📂 Analogy
Shared network drive at school — everyone can browse the same folders at the same time
📂 Analogy
A blank hard drive you plug in — you format it, only your computer uses it at once
📂 Analogy
A public cloud drive (like Google Drive) — you get files via a link (URL), from anywhere
3.4 Comparison & Use Cases
TypeAccessSimultaneous?Best forCloudEats example
File File path (NFS/Samba) ✅ Many machines Shared config, media uploads, legacy apps Shared config file for all 3 microservices
Block Raw disk (iSCSI) ❌ One machine Databases, OS drives, high-performance I/O MySQL database data files
Object HTTP REST (GET/PUT) ✅ From anywhere Images, videos, backups, large static files Menu item photos served via URL
💬

4 Networking Basics in the Cloud 60 min
🔗 Everything in this hour connects directly to what you saw in the labs: Why did -p 3000:80 make the app accessible? (port mapping) · Why could the web container reach redis by name? (internal DNS) · What stops random internet users from reaching your database? (security groups)
4.1 Virtual Private Cloud (VPC) 15 min

A VPC is your own private, isolated section of a cloud provider's network. No other customer can see or reach your resources unless you explicitly allow it.

  • RegionPhysical location of the data centre (Singapore, KL). Resources in different regions can't communicate by default.
  • CIDR BlockThe IP address range for your VPC — e.g. 10.0.0.0/16 = 65,536 possible IPs. You don't need to calculate it, just recognise the notation.
  • Public SubnetHas a route to the internet gateway. Resources here can be reached from outside — web server, load balancer.
  • Private SubnetNo route to the internet. Only reachable from inside the VPC — database, internal APIs.
🔗 Lab connection: In Lab 2.2, Redis had no -p flag — it couldn't be reached from your browser. That is the Docker equivalent of a private subnet. Only containers on cloudeats-net (the "VPC") could reach it.
4.3 Security Groups 10 min

A security group is a virtual firewall — a list of rules controlling what traffic is allowed in and out of a cloud resource.

TCP :22 (SSH)YOUR IP only ⚠️
OutboundAll allowed ✅
🗄️ CloudEats Database Rules
Inbound
TCP :3306 (MySQL)web-sg only 🔒
0.0.0.0/0BLOCKED ❌
OutboundAll allowed ✅
⚠️ Principle of least privilege: Only allow the minimum access needed. Opening MySQL port 3306 to 0.0.0.0/0 (the whole internet) lets attackers attempt brute-force attacks on your database. This is a real and common mistake.

4.5 Load Balancing 10 min
❌ Without Load Balancer
1,000 users → single web server
Server overloaded → slow or crashed
One server fails = all users affected
✅ With Load Balancer
1,000 users → load balancer → 3 servers
~333 users per server — manageable
One server fails → traffic rerouted automatically
↻ Round Robin
Send each new request to the next server in sequence: 1, 2, 3, 1, 2, 3…
📊 Least Connections
Always send to the server with the fewest active connections currently.
📌 IP Hash
Same user always goes to the same server — useful for session-based apps.

Mid-Term Quiz Preparation — Week 2 Topics
📋 The mid-term quiz is in Week 5. These are the likely Week 2 question types based on the learning objectives.
1. Which storage type would you use to store a MySQL database's data files?
  • File storage (NFS/Samba)
  • Block storage (iSCSI/EBS) — single machine, high-performance, raw disk access
  • Object storage (S3) — accessed via HTTP REST API
  • Any of the three — they are interchangeable
2. What is a VPC?
  • A virtual machine running on a physical server
  • Your own private, isolated network section in the cloud — other customers cannot see your resources unless you allow it
  • A type of load balancer that routes traffic based on IP
  • A managed DNS service that maps domain names to containers
3. The CloudEats database should be in a private subnet. Why?
  • Private subnets are faster than public subnets
  • MySQL cannot run in public subnets
  • A private subnet has no route to the internet — users on the internet cannot directly reach the database, reducing attack surface
  • Public subnets cannot store databases
4. A security group rule says: Allow TCP port 3306 from web-server-security-group. What does this mean?
  • Anyone with port 3306 open can reach the database
  • Only resources that belong to the web-server security group can connect to MySQL on port 3306 — all other sources are blocked
  • Port 3306 is open to the whole internet from the web server
  • The web server blocks all traffic to port 3306
5. In Lab 2.2, the Node.js app connects to Redis using hostname redis instead of an IP address. What provides this name resolution?
  • The host machine's /etc/hosts file
  • A manually configured DNS server you installed
  • Docker's built-in embedded DNS server (127.0.0.11) on custom bridge networks — it maps container names to their current IP automatically
  • Redis listens on a special broadcast address that all containers can reach
