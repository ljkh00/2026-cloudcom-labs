VM Configuration
›

  • b
    Name: CloudEats-Dev  |  Type: Linux  |  Version: Ubuntu (64-bit)
  • c
    Memory: 4096 MB (4 GB)  |  Hard disk: 25 GB (create new)
  • d
    After creation → click Settings → Network
  • e
    Adapter 1 → Attached to: NAT (for internet access)
  • f
    Adapter 2 → Enable ✓ → Attached to: Host-only Adapter (for VS Code access from your computer)
🌱 NAT = your VM can reach the internet through your host. Host-only = your laptop can talk to the VM directly. Both are needed!
⚡ The dual-network setup mirrors a cloud server: NAT = public interface (egress to internet), Host-only = private interface (internal network). In AWS, these map to public subnet and private subnet respectively.
🚀 VirtualBox's Host-only network uses a virtual NIC (typically vboxnet0). This is conceptually similar to a VPC's private subnet with no internet gateway. The NAT adapter uses VirtualBox's built-in NAT engine — note that incoming connections are blocked by default (no port forwarding set up yet), matching the default deny-inbound posture of a cloud security group.

Initial System Setup
Update & install tools
›

Login to your VM and run these commands:

🐧 bash
# Update system packages (always do this first!)
sudo apt update && sudo apt upgrade -y

# Install essential tools
sudo apt install -y curl wget git vim nano tree htop net-tools

# Install build tools (needed for compiling software)
sudo apt install -y build-essential software-properties-common apt-transport-https ca-certificates gnupg lsb-release
🌱 sudo = "do this as admin". apt = Ubuntu's app store for installing software. The -y flag means "yes to all" so you don't have to confirm each package.
⚡ apt update refreshes the package index (list of available software). apt upgrade installs the latest versions. Always run both before installing anything to avoid dependency conflicts.
5
Install Docker
Foundation for containers
›
🐳 Why Docker? It's the foundation of cloud containerisation. We're installing it now but you'll learn what it does in Week 3. Think of it as installing a tool you'll use later.

First, check the official docs for current steps:

  • 1
    Docker Engine Docs — follow the 3 installation steps on the page
  • 2
    Docker Compose Plugin Docs — install as a Docker plugin

Or use these commands (may need updating — check docs if they fail):

🐧 bash · Docker Install
# Add Docker's official GPG key (security verification)
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

# Add Docker repository to apt sources
echo "deb [arch=amd64 signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Update and install Docker Engine
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io

# Add your user to the docker group (so you don't need sudo every time)
sudo usermod -aG docker $USER

# Restart system to apply group membership
sudo reboot
🚀 The GPG key verification step is crucial for supply-chain security. Adding the official key ensures packages are cryptographically verified to be from Docker Inc. — preventing a MITM attack from substituting a malicious package. The user group addition avoids running containers as root, following the principle of least privilege.

Create Configuration Files
Docker Compose + .gitignore
›

In VS Code, click docker-compose.yml and paste:

📄 docker-compose.yml
services:
  web:
    image: nginx:alpine
    ports:
      - "3000:80"
    volumes:
      - ./frontend:/usr/share/nginx/html:ro
    restart: unless-stopped

  database:
    image: mysql:8.0
    environment:
      MYSQL_DATABASE: cloudeats_dev
      MYSQL_USER: developer
      MYSQL_PASSWORD: dev_password
      MYSQL_ROOT_PASSWORD: root_password
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql
    restart: unless-stopped

  cache:
    image: redis:alpine
    ports:
      - "6379:6379"
    restart: unless-stopped

volumes:
  mysql_data:

Now open .gitignore and paste:

📄 .gitignore
node_modules/
__pycache__/
*.pyc
venv/
.env
.env.local
*.log
logs/
*.sqlite
*.db
.DS_Store
Thumbs.db
.vscode/
.idea/
🌱 .gitignore tells Git to ignore certain files — things like passwords (.env), temporary files, or massive folders (node_modules) that don't need to be saved in version control.
🚀 The docker-compose.yml defines a 3-tier stack: nginx (web/reverse proxy, port 3000), MySQL (relational DB, port 3306), Redis (in-memory cache, port 6379). We're using named volumes (mysql_data) for data persistence — without this, database data would be lost when the container restarts.

Part 5
VS Code Remote-SSH from Windows 11
⏱ ~15 min (one-time)
🔗 What this does: Your VS Code editor runs on Windows, but all files, terminals, and Docker commands run inside the Linux VM. No copy-paste issues, no file sync — it just feels like the VM is local. This is your primary workflow for the entire semester.
🌱 Prerequisite: You need VS Code installed on your Windows 11 laptop. Download it free from code.visualstudio.com. If you're on a college lab PC without admin rights, use Option A (browser / code-server) instead.
⚡ SSH (Secure Shell) is a protocol for securely connecting to a remote machine over a network. The same steps you follow here — IP address, username, password or key — are identical to connecting to an AWS EC2 instance. You're learning real-world skills.
🚀 VS Code Remote-SSH installs a small server-side agent on the Linux VM the first time you connect. Extensions, language servers, and linters all run on the VM — not Windows. This is why the IntelliSense "just works" for Node.js even though Node isn't installed on your Windows host.
15
Confirm SSH is Running & Get VM IP
Pre-flight check
›

Run these commands inside your Linux VM (VirtualBox console or code-server terminal):

🐧 bash · inside VM
# 1. Confirm OpenSSH server is active
sudo systemctl status ssh

# Expected: "Active: active (running)" in green
# If not running:
sudo systemctl enable --now ssh

# 2. Find your Host-only adapter IP
ip addr show
# Look for an IP on the 192.168.56.x range
# That's your Host-only NIC — the one Windows can reach

# 3. Print it cleanly
hostname -I
# Usually two IPs: 10.0.2.x (NAT/internet) and 192.168.56.x (Host-only)
# Write down the 192.168.56.x one — you'll need it in the next step
⚠️ Use the 192.168.56.x IP (Host-only adapter), not the 10.0.2.x NAT IP. The NAT IP is for internet access only — it can't receive SSH connections from Windows.
🌱 Didn't see 192.168.56.x? Your Host-only adapter might not be enabled. In VirtualBox → select your VM → Settings → Network → Adapter 2 → check "Enable Network Adapter" → Attached to: Host-only Adapter. Then restart the VM.
🚀 VirtualBox's Host-only adapter creates a virtual LAN between your Windows host and the VM. By default it uses the 192.168.56.0/24 subnet. The VirtualBox DHCP server (vboxnet0 interface) assigns addresses automatically. In contrast, the NAT adapter uses one-way NAT — the VM can reach the internet, but the Windows host cannot initiate connections to the VM on that interface.

Configure SSH Connection
Add your VM as a host
›

Method 1 — Quick connect (beginner-friendly):

  • a
    Press Ctrl + Shift + P → type Remote-SSH: Connect to Host → press Enter
  • b
    Click "+ Add New SSH Host..."
  • c
    Type: developer@192.168.56.xxx (replace xxx with your actual IP from Step 15)
  • d
    Select the first config file when asked where to save it (usually C:\Users\YourName\.ssh\config)

Method 2 — Edit SSH config directly (recommended for reuse):

On Windows, open Notepad or VS Code and create/edit the file at C:\Users\YourName\.ssh\config:

💻 Windows · ~/.ssh/config
Host cloudeats-vm
    HostName 192.168.56.xxx
    User developer
    Port 22
    ServerAliveInterval 60
    ServerAliveCountMax 3

Replace 192.168.56.xxx with your actual VM IP. Save the file.

🌱 The Host cloudeats-vm line is just a friendly name — you can call it anything. It's what you'll see in the VS Code connection list. The HostName is the actual IP address your VM has.
⚡ ServerAliveInterval 60 sends a keep-alive packet every 60 seconds so the SSH connection doesn't drop during lab sessions. This matters when you're waiting for long Docker builds — without it, an idle SSH session can disconnect after a few minutes.
🚀 SSH config files support multiple hosts and can specify per-host keys (IdentityFile), jump hosts (ProxyJump), and port forwarding rules. In Week 7 Lab 2, GitHub Actions uses the same ~/.ssh/config pattern on the runner to SSH into your deployment VM automatically.

Troubleshooting

Click a problem to see its fix.

🔌
VS Code Remote-SSH: "Connection refused" or timeout
›

This usually means SSH is not running on the VM, or you're using the wrong IP.

🐧 bash · inside VM
# 1. Check SSH service is running
sudo systemctl status ssh
sudo systemctl enable --now ssh   # start and enable on boot

# 2. Confirm which IP to use (Host-only = 192.168.56.x)
ip addr show | grep "192.168"

# 3. Test SSH locally (from inside the VM)
ssh developer@localhost            # should succeed

# 4. Check firewall isn't blocking port 22
sudo ufw status
sudo ufw allow ssh

If the Host-only IP is missing: VirtualBox → VM Settings → Network → Adapter 2 → must be enabled and set to Host-only Adapter. Restart the VM after changing.

🔑
VS Code Remote-SSH: "Permission denied (publickey)"
›

This happens when VS Code is trying to use an SSH key instead of a password, or the key is not set up correctly.

💻 Windows PowerShell
# Option 1: Force password auth — add this to ~/.ssh/config on Windows
Host cloudeats-vm
    HostName 192.168.56.xxx
    User developer
    Port 22
    PreferredAuthentications password
    PubkeyAuthentication no

# Option 2: If using keys, check the public key is on the VM
# Run this on Windows:
ssh-copy-id developer@192.168.56.xxx
📡
VS Code Remote-SSH: VM IP keeps changing
›

VirtualBox DHCP may assign a different Host-only IP after a restart. Fix it by assigning a static IP on the VM:

🐧 bash · inside VM · Netplan static IP
# Find your Host-only interface name (look for enp0s8 or similar)
ip addr show

# Create a Netplan config for a static IP
sudo nano /etc/netplan/99-host-only.yaml

Paste this content (replace enp0s8 if your interface name is different):

📄 /etc/netplan/99-host-only.yaml
network:
  version: 2
  ethernets:
    enp0s8:
      dhcp4: no
      addresses:
        - 192.168.56.10/24
🐧 bash
sudo netplan apply
ip addr show enp0s8   # Should now show 192.168.56.10

Update your Windows ~/.ssh/config HostName to 192.168.56.10. The IP will now be the same every reboot.

  • Close other applications on your host computer
  • Check that virtualisation is enabled in BIOS (Intel VT-x / AMD-V)

6. Why should you use the 192.168.56.x IP (Host-only) and NOT the 10.0.2.x IP (NAT) for SSH?

  • The NAT adapter is one-way only — the VM can reach out but Windows cannot initiate connections to it; the Host-only adapter allows bidirectional communication
