The Electricity Analogy: You don't generate your own electricity at home — you plug into a shared grid and pay for what you use. Cloud computing works the same way. Instead of owning and managing your own servers, you access shared computing resources (power, storage, software) over the internet, on demand, and pay only for what you consume.
☁️
Cloud Computing Defined
The core idea
🌱 Beginner
Cloud computing means using other people's computers (servers) over the internet. Instead of buying expensive hardware, you rent computing power when you need it and pay only for what you use — like renting a car instead of buying one. The three key ideas are: on-demand access (available anytime), scalability (get more or less as needed), and pay-as-you-go (no large upfront costs).
⚡ Average
Cloud computing is the delivery of computing services — servers, storage, databases, networking, software — over the internet ("the cloud"). The key characteristics are: on-demand self-service (provision resources without human interaction), broad network access (available over the internet from any device), resource pooling (shared among multiple users), rapid elasticity (scale up/down quickly), and measured service (pay for what you use). These are the NIST 5 essential characteristics.
🚀 Advanced
Cloud computing follows the NIST SP 800-145 definition. Beyond consumption, understand the economic driver: CapEx (capital expenditure) shifts to OpEx (operational expenditure), enabling businesses to avoid the depreciation cycle of on-premises hardware. The elasticity model enables both horizontal scaling (more instances) and vertical scaling (larger instances). Consider also the shared responsibility model — the provider manages infrastructure, while tenants manage configuration and data. Critically evaluate trade-offs: vendor lock-in, latency, compliance (GDPR, PDPA), and data sovereignty issues.

    🔧 Cloud Service Models

    Cloud services come in three main flavours. The key difference is how much you manage versus how much the provider manages.

    🍱
    The Meal Analogy: Think about how you can get a meal — you can buy raw ingredients and cook everything yourself (IaaS), use a meal kit where ingredients are prepared but you still cook (PaaS), or just order takeout where everything is done for you (SaaS). More control = more responsibility.
    IaaS
    Infrastructure as a Service
    Raw infrastructure — you manage the OS and above
    🥩 "You buy the raw ingredients"
    • Virtual machines, storage, networking
    • You manage: OS, runtime, middleware, data, apps
    • Provider manages: servers, storage, networking hardware
    • Example: AWS EC2, Azure VMs, Google Compute Engine
    • Best for: Custom environments, legacy app migration
    PaaS
    Platform as a Service
    A platform to build on — focus on your code, not the OS
    🍱 "Meal kit — ingredients provided"
    • Managed runtime, middleware, databases
    • You manage: Applications and data only
    • Provider manages: OS, runtime, middleware, servers
    • Example: Heroku, AWS Elastic Beanstalk, Google App Engine
    • Best for: Developers who want to focus on code, not infra
    SaaS
    Software as a Service
    Ready-to-use software — just sign in and use it
    🚗 "Takeout — everything done for you"
    • Complete applications delivered via browser
    • You manage: Your own data and user settings only
    • Provider manages: Everything else
    • Example: Gmail, Microsoft 365, Salesforce, Dropbox
    • Best for: End users, businesses wanting zero IT overhead

    How to Compare Providers
    A framework for decision-making
    🌱 Beginner
    At this stage, you don't need to worry about which is "best." They all offer similar fundamental services. Think of them like mobile networks — different pricing plans, different coverage, but they all let you make calls. Focus on learning the concepts; the specific provider you use later is just syntax.
    ⚡ Average
    When comparing providers, evaluate: service breadth (how many managed services?), pricing model (compute per second vs per hour, free tier limits), geographic regions (important for latency and data residency), ecosystem lock-in risk, and certifications available (AWS SAA, Azure AZ-900, GCP ACE). For Malaysia/Southeast Asia context, all three have Singapore regions, with Alibaba Cloud offering a KL region.
    🚀 Advanced
    Analyse provider selection through multiple lenses: technical (does the managed service meet your SLA requirements?), financial (Reserved vs Spot vs On-demand pricing; compare egress costs), compliance (PCI DSS, HIPAA, PDPA alignment), and strategic (avoid single-vendor lock-in via Kubernetes + Terraform abstraction). Multi-cloud architectures using IaC tools like Terraform allow workload portability. Evaluate WAF (Well-Architected Framework) equivalents across providers: AWS WAF, Azure Well-Architected, GCP Cloud Architecture Framework.

    Cloud Benefit Analysis — Case Study
    Beginner Average Advanced Group
    ›

    🌱 Beginner
    Discuss: What problems might they face if they buy their own server? How could the cloud help? List 3 benefits of using cloud for this restaurant. Which service model (IaaS, PaaS, SaaS) makes most sense for a team with limited IT skills? Why?
