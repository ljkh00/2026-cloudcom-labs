⚠️
The single point of failure problem: All seven CloudEats services run on one physical machine. If the Proxmox server loses power, the hard drive fails, or traffic triples during a lunch rush — there is no fallback. Cloud infrastructure solves this with multiple availability zones, managed databases with automatic failover, and auto-scaling. This is the core motivation for cloud migration.
2
Understand what "managed service" means

The most important concept in this lab. A managed service is one where the cloud provider handles the operational work — installation, patching, backups, failover — so you only think about configuration and data.

🌱 Beginner — concrete example
When you ran MySQL in Docker, you were responsible for: installing MySQL, configuring it, running backups, applying security patches, and restarting it if it crashed. A managed MySQL service (like AWS RDS) does all of that automatically. You just connect to it like any other database — using the same connection string you already know.
TaskSelf-managed (Docker on VM)Managed cloud service
InstallationYou install MySQL manuallyAlready running — you just connect
Security patchesYou schedule and apply updatesProvider patches automatically in maintenance window
BackupsYou write and schedule backup scriptsAutomatic daily backups with point-in-time recovery
FailoverIf the container crashes, you restart itAutomatic promotion of a standby replica in seconds
Scaling storageYou resize the disk, migrate dataStorage auto-grows to a configured maximum
MonitoringYou set up your own alertsBuilt-in metrics, alerts, slow query logs

Part 3 Identify Migration Blockers ⏱ 15 min
4
Find what needs to change before CloudEats is cloud-ready

Moving the containers is the easy part. Several things in the current setup would break or create security risks in a cloud environment. These are your blockers — they must be fixed before or during migration.

🌱 Beginner — what is a blocker?
A blocker is anything that stops you from migrating successfully. Think about: credentials that are stored in an unsafe way, services that assume they are on the same machine, and features that require a public internet address to work properly.
BlockerWhy it is a problemHow to fix itPriority
Credentials in .env file The .env file is copied to the server by hand. In the cloud, secrets must be stored in a secret manager — never on disk or in environment files that could be committed to Git. Store all secrets in AWS Secrets Manager / Azure Key Vault. Inject at runtime via the container platform's secret injection feature. High
No HTTPS / SSL certificate The app currently runs on HTTP. A cloud deployment needs HTTPS — browsers block mixed content and users should never send passwords over unencrypted connections. Attach a TLS certificate to the load balancer or managed gateway. AWS Certificate Manager and Azure App Service provide free certificates. High
Database data migration The MySQL, MongoDB, and Redis data lives inside Docker volumes on the Proxmox VM. This data must be exported and imported into the managed cloud databases — it will not move itself. Dump MySQL with mysqldump, MongoDB with mongodump. Import into managed services. Test thoroughly before cutting over. High
Hardcoded service URLs
(e.g. localhost:3001)		 Services probably reference each other by localhost or a fixed IP. In the cloud, each service has its own URL or DNS name — these references will break. Write your fix here… (Hint: use environment variables for service URLs) Medium
No health check routes Cloud load balancers require a /health endpoint to confirm a service is ready to receive traffic. Without it, the load balancer cannot verify the service started successfully. Write your fix here… (Hint: a simple GET /health returning 200 is enough) Medium
GitHub Actions SSH deploy script The current CI/CD pipeline SSHs into the Proxmox VM. After migration, it needs to deploy to the cloud platform instead — a different target with a different authentication method. Write your fix here… (Hint: replace the SSH step with the provider's CLI deploy command) Medium
No domain name Currently accessed by IP address. A production app needs a domain name with DNS pointing to the cloud load balancer. Register a domain name. Create a DNS A record pointing to the cloud load balancer's IP. Configure the managed gateway or load balancer to handle the domain. Low
🚀 Advanced — what else breaks?
The Redis shopping cart stores session state in memory. In a horizontally-scaled deployment, a request could hit any container instance — they do not share memory. Session state must be externalised to the managed Redis service (which you already have). But the connection string must point to the cloud Redis, not localhost. This is a subtle bug that only appears under load — the classic stateful service problem.

Part 4 Write the One-Page Migration Plan ⏱ 10 min
5
Fill in the migration plan template

A migration plan is a document written for a non-technical decision-maker — your manager, a client, or an investor. It should tell them: what we are migrating, which cloud provider, how long each phase takes, what risks exist, and how we know when we are done.

🌱 Beginner — who is this document for?
Write as if your reader knows what a website is but has never used Docker or a cloud console. Avoid jargon. If you must use a technical term, define it in one sentence. The test: could your parents read this and understand what you are proposing to do?
1. Executive Summary

Two to three sentences. What is being migrated, why, and what the business benefit is. Write this last — it is easier once you have completed the rest.

CloudEats is currently running on a single on-premises server (Proxmox). This plan describes the migration of all seven application services and their databases to [choose: AWS / Azure / GCP]. After migration, CloudEats will be more reliable, able to scale during peak hours, and no longer dependent on a single physical machine that is a single point of failure.
2. Cloud Provider Chosen
Write your choice here and give one reason why: e.g. "AWS — most widely used provider; largest free tier for learning; team already has experience with it."

⚡ Average — checkpoint question
Q: A colleague says "let's do the cutover on a Friday evening." What is wrong with this plan, and when would you schedule it instead? (Think about when traffic is lowest and who is available to fix problems.)
🚀 Advanced — what is missing from this plan?
A real enterprise migration plan would also include: a rollback procedure (how do you undo the migration if it fails?), a data consistency verification step (how do you confirm no records were lost or corrupted?), a performance baseline (what response time are you trying to match or beat?), and stakeholder sign-off. Write one paragraph for the rollback procedure as an advanced challenge.

🔧 Troubleshooting

⚠️ "I cannot see the Proxmox demo interface clearly"
Note what you missed and ask the instructor to replay that step. The worksheet can be completed using the architecture diagrams and your knowledge of the stack from previous weeks — the observation table is the only part that strictly requires watching the demo.
⚠️ "I do not know which cloud provider to use for the worksheet"
Pick AWS and use it consistently throughout. It has the most widely-documented service equivalents and the most examples online. The concepts are identical across providers — only the product names differ. If you already have experience with Azure or GCP, use that instead.
⚠️ "I cannot think of what to write for 'Why managed is better'"
Go back to the Step 2 self-managed vs managed table. For each component, ask: "What would I have to do myself if I ran this in a Docker container on a VM?" The answer to that question is what the managed service eliminates. Backups, patching, restart on crash, failover — these disappear.
⚠️ "My migration plan feels too short"
A migration plan should contain enough detail for a decision-maker to understand the scope and approve the work. If your success criteria column is empty, fill it in — that is the most commonly missed part. If your risk table only has one row, add at least one more. One page is a guideline, not a hard limit.
