1.1 Edge Computing & IoT ⏱ 15 min
🌱 Beginner — start here
Cloud computing means your app runs on a server in a big data centre, maybe thousands of kilometres away. Every time your app does something, it sends a message there and waits for the reply. Most of the time this is fine — the wait is so short you cannot feel it. But for a few situations, even a tiny wait is a serious problem.
🚗 Analogy — the remote controlled car
Imagine steering a remote-controlled car, but every time you push the joystick, the signal has to travel to a server in Singapore and back before the car moves. By the time the instruction arrives, the car has already hit the wall. Edge computing solves this by making decisions inside the controller in your hand — no round trip required.

The edge means any device or small server that is physically close to where data is generated — a smart camera, a sensor on a factory floor, a self-driving car's onboard computer. Processing happens there, not in a distant data centre.

🚗
Autonomous Vehicles
Must detect a pedestrian and brake in under 10 ms. A cloud round-trip takes 50–200 ms. Processing must happen on the vehicle itself.
🏭
Smart Factories
A temperature sensor must trigger a machine shutdown in milliseconds. A network outage cannot be allowed to stop the safety system.
🏥
Hospital Patient Monitors
Heart rate alarms cannot depend on an internet connection. Critical decisions happen on-device; only summaries are sent to the cloud.
☁️ Cloud-only approach
  • All processing in a distant data centre
  • 50–200 ms round-trip latency
  • Fails completely without internet
  • Bandwidth cost: every sensor reading uploaded
  • Good for: dashboards, analytics, long-term storage
📡 Edge + Cloud hybrid
  • Decisions made locally, summaries sent to cloud
  • <1 ms latency for local decisions
  • Continues working offline
  • Only important events uploaded — lower cost
  • Good for: realtime control, safety, IoT sensors
🚀 Advanced
AWS Greengrass, Azure IoT Edge, and Google Cloud IoT Core all let you deploy containerised Lambda/Functions directly to edge devices. The same container runtime you used in Weeks 2–7 runs on a Raspberry Pi at the edge. The architecture pattern is called fog computing — a layer of small processing nodes between the device and the cloud. Kubernetes at the edge (K3s) is increasingly used for managing fleets of edge devices.
1.2 AI/ML as a Cloud Service ⏱ 15 min
🌱 Beginner — plain English first
AI (Artificial Intelligence) means making a computer do things that normally require human intelligence — like recognising faces, understanding speech, or translating languages. ML (Machine Learning) is one technique for building AI: instead of writing rules, you train the computer on millions of examples and it learns patterns itself. This is hard to build from scratch. Cloud providers offer ready-made AI/ML as a simple API call — so you can add smart features to your app without training a single model.
☕ Analogy — buying bread vs baking it
Training your own AI model is like building a bakery from scratch, buying wheat, and milling your own flour. Using a cloud AI API is like buying a loaf from the supermarket. For 90% of apps, buying is the right answer. Build from scratch only if you need something the supermarket does not sell.

What cloud AI services can do for CloudEats (without training anything)

📷
Vision — Image Recognition
Upload a photo of food → get back "burger", "fries", "drink" as labels. Use case: let restaurant owners tag menu items by photo. AWS Rekognition, Azure Computer Vision, GCP Vision API.
💬
Language — Sentiment Analysis
Send a customer review text → get back "positive", "negative", "neutral" plus a confidence score. Use case: automatically flag negative reviews for a manager. AWS Comprehend, Azure Text Analytics.
🗣️
Speech — Voice Orders
Convert a spoken order to text, then send it to the order service as a normal API call. Use case: accessibility, drive-through ordering. AWS Transcribe, Azure Speech Services.
📈
Prediction — Demand Forecasting
Send historical order data → get back predicted demand for next week. Use case: tell the kitchen how much stock to prepare. AWS Forecast, Azure Machine Learning, Vertex AI.
Why this matters for your career: You do not need to be a data scientist to use AI. You need to know the API exists, when to reach for it, and how to connect it to your existing services. That is exactly what you have been doing all semester — connecting services via APIs.
⚖️
Ethics checkpoint: AI services can reflect biases in their training data. Face recognition has been shown to perform worse on darker skin tones. Sentiment analysis can misread cultural expressions. As the developer integrating these services, you carry responsibility for how the output is used — even if you did not build the model.
⚡ Average — checkpoint question
Q: A CloudEats competitor wants to add an automatic food photo tagger to their menu management page. A developer suggests training a custom image recognition model. What questions would you ask before deciding whether to train from scratch vs use a cloud AI API?

Hint: think about cost, time to market, data availability, and accuracy requirements.
1.3 Multi-Cloud vs Hybrid Cloud ⏱ 15 min

Two terms that are often confused. They are distinct strategies with different motivations.

☁️☁️ Multi-Cloud

Definition: Using two or more public cloud providers simultaneously (e.g. AWS + GCP).

  • Avoid vendor lock-in
  • Use best-of-breed services (AWS for compute, GCP for AI/ML)
  • Negotiate better pricing
  • Geographic redundancy across providers

⚠️ Adds operational complexity — two consoles, two billing systems, two security models

🏢☁️ Hybrid Cloud

Definition: On-premises infrastructure connected to a public cloud (e.g. Proxmox + AWS).

  • Regulatory compliance (data must stay in-country)
  • Existing hardware investment is not wasted
  • Burst to cloud during peak load (cloud bursting)
  • Banks, hospitals, government agencies use this most

⚠️ Requires a network connection between on-prem and cloud (VPN or dedicated link)

💡
CloudEats connection: The Proxmox environment you have been using is an on-premises infrastructure. If CloudEats deployed to AWS but kept the Proxmox server for development and disaster recovery, that would be a hybrid cloud setup. The migration plan in Lab 10.1 is the first step of moving from on-prem to cloud — or choosing a hybrid architecture deliberately.
🌱 Beginner — one-sentence memory aid
Multi-cloud = "We use multiple cloud providers."
Hybrid cloud = "We use our own servers AND a cloud provider together."
1.4 What's Next in Cloud — Emerging Signals ⏱ 15 min
⚡
Serverless 2.0 — Faster Cold Starts
Early serverless (AWS Lambda 2014) had slow startup times — 500ms to 3 seconds on first request. Providers have reduced this to under 100ms with container snapshots. AWS Lambda SnapStart, Google Cloud Run Gen 2. Serverless is becoming viable for APIs that previously required always-on containers.
🤖
AI-Assisted Development
Code generation tools (GitHub Copilot, Amazon CodeWhisperer, Claude Code) are changing how developers work. The skill is shifting from "can you write this function?" to "can you review, test, and architect this system?" The cloud knowledge in this course becomes more valuable, not less.
🌱
Sustainable Cloud
Cloud providers publish carbon emissions data per region. AWS's us-east-1 vs eu-west-1 have significantly different carbon footprints. Right-sizing (Week 9) is also a sustainability practice. Some certifications now include sustainability as a design principle.
🔒
Zero Trust Security
The old model: trust everything inside the network perimeter. Zero Trust: verify every request, every time, regardless of where it comes from. The JWT + RBAC architecture from Week 8 is a zero trust pattern — you implemented this without knowing the name for it.
🚀 Advanced — what breaks if you lean too far
Multi-cloud sounds attractive but introduces a hidden cost: you now need engineers who know both AWS and GCP deeply. Most startups choose one provider and go deep. The architectural principle worth internalising is avoid proprietary lock-in at the data layer — using standard formats (Postgres, not proprietary DBs; S3-compatible APIs) gives you exit options without the full operational overhead of running two clouds simultaneously.

Every single component in your Docker Compose stack has a cloud equivalent. This is not coincidence — Docker was designed to mirror cloud-native patterns.

Node.js container→Container hosting (ECS, Cloud Run, Container Apps)Same image, managed host

Best if: you want a recognised credential and structured learning

✏️ Exam Tips & Week 10 Summary ⏱ Final review

Topics most likely to appear — Week 10

Q: Describe edge computing and give one real-world use case.
Answer structure: (1) define edge — processing at or near the data source rather than in a distant data centre; (2) name a latency-sensitive use case — autonomous vehicles, factory sensors, patient monitors; (3) explain why the cloud round-trip is unsuitable for that use case.
Q: Distinguish multi-cloud from hybrid cloud with one sentence each.
Multi-cloud: using two or more public cloud providers simultaneously. Hybrid cloud: combining on-premises infrastructure with a public cloud. Common mistake: saying hybrid means "two clouds" — it specifically means on-prem plus cloud.
Q: A developer wants to add face recognition to a food delivery app's driver verification. Should they train a custom ML model or use a cloud AI API? Justify.
This is a trade-off question. Cloud AI API is correct for most cases: faster to market, lower cost, no ML expertise needed, provider maintains accuracy. Custom model justified only if: data is sensitive (cannot send to third-party API), accuracy requirements are specialised, volume is high enough that API costs exceed training costs.

Synthesis questions — any week

Q: Given a CloudEats scenario, choose the correct database type and justify.
MySQL → structured relational data with fixed schema (users, menu items). MongoDB → flexible document data with varying fields (order documents). Redis → ephemeral data requiring sub-millisecond reads (shopping carts, sessions). Wrong answer: choosing MongoDB "because it is more modern" without justification.
Q: Draw the request flow from a user's browser to the order service through the API Gateway.
Browser → HTTPS request to API Gateway (:8000) → Gateway verifies JWT → Gateway routes /orders to order-service (:3003) → order-service queries MongoDB → response returned through Gateway to browser. Include: JWT check happens at the gateway, not at each service.
Q: CloudEats receives 10x normal traffic during a peak event. What cloud strategies would you use?
Horizontal scaling (add more container instances), auto-scaling groups, Redis caching for menu data (Week 9), CDN for static assets, load balancer to distribute traffic across instances, managed database with read replicas. Mention monitoring + alerts (Week 9) to detect the spike before it becomes an outage.
